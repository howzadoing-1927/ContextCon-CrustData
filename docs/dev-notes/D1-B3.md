- Ticket: B3. Branch: `feat/backend-core`. Base: `4dc23ed`. This commit also carries the B2 test fixes: deterministic lease expiry and redacted secrets in test output.
- Contract: `outcome.v1`. Additive types: `OrganizationView`, `WebsiteSource`, `PastedTextSource`, `ProfileUpdate`, `PolicyUpdate`, `NormalizedPlan`.

## Routes changed
- `GET /workspace`, `PUT /workspace/profile`, `PUT /workspace/policy` and `POST /workspace/sources`: new.
- `POST /campaigns`: the launch gate now requires approved, evidence-backed facts and complete consent (`consent_record` + `consented_at`), share-locks the organization row, and stores the launch snapshot.
- Worker: `normalize_mission` handler, registered only when Azure is configured.

## Model path
- One API family: Chat Completions with `response_format` `json_schema` (strict).
  - If a deployment rejects strict schemas, it falls back to `json_object` and records that.
  - `AZURE_OPENAI_API_VERSION` set: classic `AzureOpenAI`. Empty: the Azure v1 endpoint `<endpoint>/openai/v1/`.
- Routing: fast deployment first, then decision; the fallback is recorded as `degraded_from`.
- Prompt: doc 04 shared policy plus the mission-normalization role, verbatim (`normalize_mission.v1`).
  - The envelope holds the operator request, the approved fact IDs and texts, forbidden promises, date/timezone, limits and the output schema.
  - It never holds recipient emails, evidence IDs, tokens or tenant data.
- Local validation with Pydantic `NormalizedPlan` (`extra=forbid`). One repair attempt; after that, blocked.
- Deterministic plan policy:
  - Query count no higher than `max_research_calls`.
  - Each query limit no higher than `max_discovered`.
  - No URL, SQL or script syntax in intents.
  - Not empty unless `missing_required_fields` is non-empty.
- Ledger: every attempt is recorded (deployment, model version, prompt version, tokens, latency, output mode) and added to `campaigns.budget_json.usage`. The budget is checked before calling.

## Limitations
- Only the fast deployment is exercised by `normalize_mission`. The decision deployment passed a smoke call but has no production role until reply interpretation and verification (B5/B6).
- The plan can encode inferred bounds as rules. For example, "mid-market" became a 50–1,000 employee range, though the model also listed it as a hypothesis. B4/B5 must treat assumption-derived rules as unknown, not as verified must-haves.
- Website text is stored in `evidence.excerpt` (up to 60k characters), not yet as a snapshot in Storage. There is no automatic fact proposal from website text; the operator writes approved facts citing evidence IDs.
- Profile approval and policy changes aren't in the campaign-scoped decision ledger, because decisions require a campaign. The organization row records who approved, when, and the approval key and hash.
- No `/decisions/{id}/resolve` yet, so a `needs_human` clarification can't be resolved through the API.
- Research tasks queued after an accepted plan stay `ready` until B4.
