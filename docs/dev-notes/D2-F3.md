# D2-F3 — Web console (apps/web) against fixtures

Branch `feat/google-web`. The UI runs on a fixture transport (`NEXT_PUBLIC_API_MODE=fixture`, the default) with a scenario picker in the bottom bar. Switching to `live` uses the same `OutcomeClient` over HTTP, so nothing below the transport changes.

## Run

```
cd apps/web && pnpm install && pnpm dev -p 3100
```

There is no sign-in for now. `/` is the founder landing page: the founder enters a website, the brief fills in from it, they review and approve it, and Continue opens `/setup`. "Use the demo company" runs the same flow for `demo-seller.example`. `/signin` and `/orgs` redirect to `/`, and so does the console when there is no session. The leave button in the top bar clears the session and the saved brief.

`?fixture_session=1` still starts the synthetic session directly (fixture mode only) for screenshots and design scans. `#resolve` on a mission URL opens its exception drawer.

## Contract requests for D1

1. **Workspace view.** `GET /organizations/{id}` returning `OrganizationView` as typed in `apps/web/src/lib/contracts/index.ts`: profile (version, approved/proposed facts, FAQ, forbidden promises), sources, `evidence: EvidenceView[]`, policy (config_version, consented recipients, working hours, calendar, limits), Google connection, `viewer_role`.
2. **Memberships.** `GET /me/memberships` → `[{organization_id, organization_name, role}]`. The org picker is hidden while sign-in is removed.
3. **Per-item `execution_label`** (`LIVE | CACHED | FIXTURE | SIMULATED_BUYER`) on decisions, messages, evidence and the booking receipt. Today the UI derives it from transport mode, or LIVE when a provider id exists.
4. **`declined` conversation state** distinct from `stopped`, so the route can show "Buyer declined".
5. **Google status schema.** `status` (`connected | reauth_required | revoked | not_connected`), `account_email`, `calendar_id`, `granted_scopes[]`; UI compares against the four required scopes.
6. **`clarify_time` resolution value** shape: `{ reoffer_slot_ids: string[] }`. Resolutions carry `expected_conversation_version`; allowed types come from `proposed_action.resolution_types`.
7. **Ledger ordering.** Decisions paged oldest-first with a stable cursor; `last_decision_id` + `version` on the mission detail so the client knows when to refetch.
8. **Health.** `/health/ready` body on 503 should still include `database`, `worker`, `last_seen_age_seconds` (the banner reads them).
9. **Campaign list** lacks conversation state, so list rows show stage text, not a route.
10. **Founder brief.** Typed in `contracts/index.ts`, fixture in `lib/fixtures/onboarding.ts`.
    - `POST /workspace/website-analysis {url}` → `WebsiteAnalysis`: `pages_read[]`; each field as `{value, page}` with `value: null` when the site doesn't state it; `proposed_facts[]` with evidence ids; `evidence: EvidenceView[]` (`seller_website`, `observed`). Same public-HTTPS and private-address rules as source ingest. It never returns founder identity, and returns pricing only when a page states it.
    - `PUT /workspace/brief` (`BriefSave`, CAS on `expected_profile_version`) writes name, website, timezone, the description as an approved fact, the founder-ticked claims as approved (the rest stay proposed), escalation topics into `forbidden_promises`, and working hours and duration into the policy. It also stores two new optional fields on `OrganizationView`: `seller_brief` (founder name and email, service, pricing, capacity) and `ideal_customer` (customer type, regions, buyer roles, timeline, criteria, exclusions). New missions prefill from `ideal_customer`.
    - Neither endpoint should need a separate sign-in step before the founder's first visit. How the live session gets created is open.
